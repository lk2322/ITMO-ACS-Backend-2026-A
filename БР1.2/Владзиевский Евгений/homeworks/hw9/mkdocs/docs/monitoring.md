# Мониторинг

Стек наблюдаемости работает рядом с кластером и доступен по адресу
[http://192.168.1.245/grafana/](http://192.168.1.245/grafana/).

| Компонент | Роль |
|---|---|
| Prometheus | метрики, retention 15 дней |
| node-exporter | CPU, память, диск и сеть виртуальной машины |
| cAdvisor | потребление ресурсов контейнерами |
| blackbox-exporter | опрос `/health` каждого микросервиса |
| Loki | логи, retention 7 дней |
| Promtail | сбор логов всех контейнеров узла |
| Grafana | дашборд «Rental App — ресурсы, доступность, логи» |

## Дашборд

1. **Ресурсы ВМ** — CPU, RAM, диск, сеть, дисковый ввод-вывод.
2. **Доступность микросервисов** — плитки UP/DOWN по шести сервисам,
   счётчик доступных, история и время ответа `/health`.
3. **Логи контейнеров** — панель с фильтрами по контейнеру и подстроке.

## Полезные запросы

```promql
# загрузка CPU виртуальной машины, %
100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# доступность сервисов
probe_success{job="blackbox-health"}

# память по контейнерам приложения
sum by (name) (container_memory_working_set_bytes{name=~"rental-app.*"})
```

```logql
# ошибки во всех контейнерах за час
{container=~".+"} |= "error"

# логи конкретного сервиса
{container="rental-app-auth-service-1"}
```

!!! note "Почему мониторинг не в кластере"
    Grafana и Prometheus работают в Docker на самом узле, а не в
    Kubernetes: система наблюдения не должна зависеть от того, за чем
    она наблюдает. При отказе кластера дашборды останутся доступными.
