# Тестирование в Postman

В каталоге `postman/` лежат два файла:

| Файл | Назначение |
|---|---|
| `Rental_API_K8s.postman_collection.json` | коллекция со сквозным сценарием и тестами |
| `Rental_API_K8s.postman_environment.json` | окружение: адрес кластера и общие переменные |

## Импорт и запуск

1. В Postman: **Import** → перетащить оба файла.
2. Выбрать окружение **Rental API — кластер k3s**.
3. Запустить коллекцию целиком: **Run collection**.

Коллекция самодостаточна: адреса почты генерируются из текущей метки
времени, поэтому повторные запуски не конфликтуют с уже созданными
пользователями, а идентификаторы объекта и аренды передаются между
запросами через переменные коллекции.

## Что проверяет сценарий

| Раздел | Проверки |
|---|---|
| 0. Доступность | `/health` отвечает, сервис — `api-gateway` |
| 1. Регистрация и вход | выдаются оба токена, роль сохраняется, повторный email отклоняется, неверный пароль даёт 401, защищённый эндпоинт без токена даёт 401 |
| 2. Справочники | типы недвижимости и удобства заполнены сидом |
| 3. Публикация объекта | владелец создаёт объект; арендатор получает 403; запрос без обязательных полей — 400 |
| 4. Поиск | фильтры по городу и цене возвращают только подходящие объекты |
| 5. Бронирование и оплата | бронь создаётся в статусе `pending`, пересечение дат даёт 409, оплата переводит аренду в `paid` |
| 6. Переписка | сообщения в обе стороны, список диалогов, история по объекту |
| 7. История | аренда видна в списке, фильтр `status=paid`, в транзакциях есть успешный платёж |

Всего 28 запросов и 74 проверки `pm.test`.

## Запуск из командной строки

```bash
npm install -g newman
newman run postman/Rental_API_K8s.postman_collection.json \
       -e postman/Rental_API_K8s.postman_environment.json
```

Такой запуск удобно добавить в CI как smoke-тест после выкатки.
